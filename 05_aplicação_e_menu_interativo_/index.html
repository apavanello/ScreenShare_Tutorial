    Chapter 5: Aplicação e Menu Interativo

    Bem-vindo(a) ao quinto e último capítulo do nosso tutorial do ScreenMatch! Até agora, construímos os blocos essenciais do nosso aplicativo: * No Capítulo 1: Entidades de Dados, definimos a estrutura dos nossos dados (Serie e Episodio). * No Capítulo 2: Serviço de Requisições Web, aprendemos a buscar informações de séries na internet. * No Capítulo 3: Conversor de Dados JSON, vimos como transformar esses dados brutos em objetos Java úteis. * No Capítulo 4: Repositório de Séries, descobrimos como salvar e recuperar nossas séries e episódios de um banco de dados.

    Agora, temos todas as peças do quebra-cabeça. Mas como o usuário interage com tudo isso? Como ele diz ao programa para "buscar uma série" ou "listar as séries que já salvei"?

    É exatamente isso que a Aplicação e Menu Interativo resolve! Ela é o "painel de controle" do nosso programa, o ponto onde o usuário se conecta com toda a funcionalidade que construímos.

    O Painel de Controle: A Classe Principal

    Imagine que você tem uma orquestra cheia de músicos talentosos (nossos serviços e repositórios), mas precisa de um maestro para coordenar tudo. No nosso aplicativo, a classe Principal é esse maestro. Ela é responsável por: * Apresentar as opções ao usuário (o menu). * Receber a entrada do usuário. * Chamar as partes certas do sistema (o Serviço de Requisições Web para buscar, o Repositório de Séries para salvar, etc.) para executar a ação desejada.

    Nosso Caso de Uso Central: O usuário deseja buscar uma nova série na internet, visualizar seus detalhes e salvá-la em nosso banco de dados.

    Exibindo o Menu e Interagindo com o Usuário

    A classe Principal possui um método central chamado exibeMenu(). Este método faz um laço contínuo, mostrando as opções e esperando pela escolha do usuário.

    Veja uma versão simplificada de como o método exibeMenu funciona:

    // src/main/java/br/com/alura/ScreenMatch/programa/Principal.java
public class Principal {
    private Scanner sc = new Scanner(System.in); // Para ler a entrada do usuário
    private SerieRepository serieRepository; // Nosso arquivista de séries

    // O Spring "injeta" o SerieRepository aqui
    public Principal(SerieRepository serieRepository) {
        this.serieRepository = serieRepository;
    }

    public void exibeMenu() {
        int escolha = -1; // Variável para a escolha do usuário

        while (escolha != 0) { // O menu continua até o usuário digitar 0 (Sair)
            System.out.println("\n--- MENU SCREENMATCH ---");
            System.out.println("1: Buscar séries na web");
            System.out.println("2: Listar séries salvas");
            System.out.println("0: Sair");
            System.out.print("Escolha uma opção: ");

            escolha = sc.nextInt(); // Lê a opção do usuário
            sc.nextLine(); // Consome a quebra de linha

            if (escolha == 1) {
                buscarSerieWeb(); // Chama o método para buscar séries
            } else if (escolha == 2) {
                // Em um app real, haveria um método para listar do banco de dados
                System.out.println("Funcionalidade de listar ainda não implementada aqui!");
            } else if (escolha == 0) {
                System.out.println("Saindo do programa. Até mais!");
            } else {
                System.out.println("Opção inválida! Tente novamente.");
            }
        }
    }

    // ... outros métodos seriam definidos aqui, como buscarSerieWeb() ...
}
    Explicação: * Scanner sc = new Scanner(System.in);: Este objeto é usado para ler o que o usuário digita no teclado. * public Principal(SerieRepository serieRepository): Este é o construtor da classe Principal. O Spring Boot é inteligente e, quando ele cria uma instância de Principal, ele automaticamente encontra e "injeta" uma instância do SerieRepository para nós. Assim, a classe Principal tem acesso direto ao nosso "arquivista" do banco de dados. * while (escolha != 0): Garante que o menu continue aparecendo até que o usuário escolha a opção "Sair" (digitando 0). * escolha = sc.nextInt();: Lê o número digitado pelo usuário. * sc.nextLine();: Essa linha é importante! Ela "limpa" a entrada do teclado após ler um número, para que a próxima leitura de texto não tenha problemas. * if (escolha == 1) { buscarSerieWeb(); }: Se o usuário digitar 1, o método buscarSerieWeb() é chamado, que inicia a busca de uma série.

    Juntando as Peças: O Método buscarSerieWeb()

    Agora, vamos ver como o método buscarSerieWeb() orquestra a busca, conversão e salvamento de uma série, usando tudo o que aprendemos nos capítulos anteriores.

    // src/main/java/br/com/alura/ScreenMatch/programa/Principal.java
import br.com.alura.ScreenMatch.entities.DadosSerie; // Nosso "mini-cartão" de dados
import br.com.alura.ScreenMatch.entities.Serie; // Nossa entidade principal
import br.com.alura.ScreenMatch.service.ScreenService; // Nosso explorador web
import br.com.alura.ScreenMatch.service.ConverterDados; // Nosso tradutor JSON

// ... dentro da classe Principal ...
public class Principal {
    // ... campos e construtor já mostrados ...

    // Constantes para a API do OMDb
    private final String ENDEREÇO = "http://www.omdbapi.com/?t=";
    private final String APIKEY = "&apikey=a64d765c";

    private ScreenService screenService = new ScreenService(); // Instância do serviço web
    private ConverterDados converterDados = new ConverterDados(); // Instância do conversor

    public void buscarSerieWeb() {
        // 1. Pede o nome da série ao usuário e busca na web
        DadosSerie dadosTemporarios = buscaSerie();

        // 2. Cria um objeto Serie a partir dos dados temporários
        Serie serieParaSalvar = new Serie(dadosTemporarios);

        // 3. Salva a série no banco de dados usando o repositório
        serieRepository.save(serieParaSalvar);

        System.out.println("\nSérie encontrada e salva:");
        System.out.println(serieParaSalvar); // Imprime a série salva
    }

    // Método auxiliar para buscar a série e obter os dados temporários
    private DadosSerie buscaSerie() {
        System.out.print("Insira o nome de uma série para buscar: ");
        String nomeSerie = sc.nextLine();

        // Constrói o endereço completo da API
        String url = ENDEREÇO + nomeSerie.replace(" ", "+") + APIKEY;

        // 1. Usa o Serviço de Requisições Web para obter o JSON
        String jsonDaWeb = screenService.obterDados(url);

        // 2. Usa o Conversor de Dados JSON para transformar o JSON em DadosSerie
        DadosSerie dadosSerie = converterDados.obterDados(jsonDaWeb, DadosSerie.class);

        return dadosSerie;
    }
}
    Explicação: * DadosSerie dadosTemporarios = buscaSerie();: O método buscarSerieWeb primeiramente chama um método auxiliar buscaSerie(). Este método é quem realmente faz a "viagem" até a internet e a "tradução" do JSON: * Ele solicita o nome da série ao usuário. * Constrói a URL completa para a API do OMDb, substituindo espaços por + (necessário para URLs). * Chama screenService.obterDados(url) (do Capítulo 2) para obter o texto JSON da série. * Chama converterDados.obterDados(jsonDaWeb, DadosSerie.class) (do Capítulo 3) para transformar o JSON em um objeto DadosSerie (nosso "mini-cartão" temporário). * Retorna esse DadosSerie. * Serie serieParaSalvar = new Serie(dadosTemporarios);: Com os dadosTemporarios em mãos, criamos um objeto da nossa entidade Serie (do Capítulo 1). A classe Serie tem um construtor que aceita DadosSerie e preenche seus próprios campos a partir dele. * serieRepository.save(serieParaSalvar);: Finalmente, chamamos o método save do nosso serieRepository (do Capítulo 4). Isso faz com que a série seja persistida, ou seja, salva permanentemente no banco de dados!

    O Ponto de Partida: A Classe ScreenMatchApplication

    Mas como o programa começa? Em um aplicativo Spring Boot, o ponto de entrada é geralmente a classe principal com a anotação @SpringBootApplication. É aqui que o menu é ativado.

    // src/main/java/br/com/alura/ScreenMatch/ScreenMatchApplication.java
package br.com.alura.ScreenMatch;

import br.com.alura.ScreenMatch.programa.Principal; // Importa nossa classe Principal
import br.com.alura.ScreenMatch.repository.SerieRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class ScreenMatchApplication implements CommandLineRunner {
    @Autowired
    SerieRepository serieRepository; // O Spring injeta o repositório aqui

    public static void main(String[] args) {
        SpringApplication.run(ScreenMatchApplication.class, args); // Inicia a aplicação Spring Boot
    }

    @Override
    public void run(String... args) throws Exception {
        // Este método é executado assim que a aplicação Spring Boot é iniciada
        Principal principal = new Principal(serieRepository); // Cria uma nova instância do nosso menu
        principal.exibeMenu(); // Chama o método que exibe o menu
    }
}
    Explicação: * @SpringBootApplication: Esta anotação diz ao Spring Boot que esta é a classe principal da sua aplicação. * public static void main(String[] args): O método principal do Java, que inicia o aplicativo Spring Boot. * implements CommandLineRunner: Ao implementar esta interface, garantimos que o método run() será executado automaticamente assim que o aplicativo Spring Boot estiver pronto. * @Autowired SerieRepository serieRepository;: O Spring injeta o SerieRepository diretamente nesta classe também, para que possamos passá-lo para o construtor da classe Principal. * Principal principal = new Principal(serieRepository);: Criamos uma instância do nosso "maestro" (Principal), passando o serieRepository que o Spring nos forneceu. * principal.exibeMenu();: Finalmente, chamamos o método exibeMenu(), e o painel de controle do ScreenMatch ganha vida!

    RepositorioDados->>BancoDeDados: Executa SQL
    BancoDeDados-->>RepositorioDados: Confirma salvamento

    1. O ScreenMatchApplication é iniciado pelo Spring Boot.
    2. Ele cria uma instância da Classe Principal (nosso "maestro") e pede para ela exibir o menu.
    3. A Classe Principal exibe as opções no console e espera a entrada do usuário.
    4. Quando o usuário escolhe "Buscar série", a Classe Principal solicita o nome da série.
    5. Em seguida, ela chama o ScreenService (nosso "explorador web") para obter os dados da série na internet, que retorna um texto JSON.
    6. O texto JSON é então passado para o ConverterDados (nosso "tradutor"), que o transforma em um objeto DadosSerie (nosso "mini-cartão" temporário).
    7. A Classe Principal usa esse DadosSerie para criar um objeto Serie completo.
    8. Finalmente, ela envia esse objeto Serie para o SerieRepository (nosso "arquivista"), que se encarrega de salvar a série no Banco de Dados.
    9. O resultado é exibido de volta para o usuário.
