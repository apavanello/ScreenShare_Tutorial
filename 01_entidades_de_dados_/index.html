    Chapter 1: Entidades de Dados

    Bem-vindo(a) ao primeiro capítulo do nosso tutorial sobre o projeto ScreenMatch! Aqui, vamos explorar como o aplicativo organiza e entende as informações sobre séries de TV e seus episódios.

    Imagine que você está criando um catálogo de filmes e séries. Para cada item nesse catálogo, você precisa de um "cartão de identificação" que contenha todas as informações importantes: título, sinopse, atores, etc. No mundo da programação, esses "cartões de identificação" são o que chamamos de Entidades de Dados. Elas são como plantas ou modelos que definem exatamente quais informações vamos guardar e como elas se relacionam.

    No ScreenMatch, nossas principais entidades de dados são Serie e Episodio. Elas nos permitem: * Guardar os detalhes de uma série completa, como "Stranger Things". * Guardar os detalhes de cada episódio dessa série, como "Capítulo Um" da 1ª temporada. * Conectar uma série aos seus episódios correspondentes.

    Vamos mergulhar em cada uma delas!

    A Entidade Serie: O Cartão Principal

    A classe Serie é o nosso "cartão de identificação" principal para uma série de TV. Ela contém todas as informações gerais sobre a série.

    No código Java, a classe Serie se parece com isso:

    // src/main/java/br/com/alura/ScreenMatch/entities/Serie.java
package br.com.alura.ScreenMatch.entities;

import jakarta.persistence.*; // Para trabalhar com banco de dados
import java.util.ArrayList;
import java.util.List;

@Entity // Diz ao Java que esta classe representa uma tabela no banco de dados
@Table(name = "series") // Define o nome da tabela no banco de dados
public class Serie {
   @Id // Indica que 'id' é a chave primária
   @GeneratedValue(strategy = GenerationType.IDENTITY) // Gera o ID automaticamente
   private Long id;
   @Column(unique = true) // Garante que o título seja único
   private String titulo;
   private Integer totalTemporadas;
   private Double avaliacao;
   @Enumerated(EnumType.STRING) // Armazena a categoria como texto
   private Categoria genero; // Nosso tipo especial para categorias!
   private String poster;
   private String sinopse;
   private String atores;

   @OneToMany(mappedBy = "serie", cascade = CascadeType.ALL, fetch = FetchType.EAGER)
   private List<Episodio> episodios = new ArrayList<>(); // Lista de todos os episódios

   public Serie() {} // Construtor padrão (necessário para persistência)

   // Métodos como getters e setters seriam definidos aqui...
   public String getTitulo() { return titulo; }
   public void setTitulo(String titulo) { this.titulo = titulo; }
   // ... e muitos outros para cada campo
}
    Explicação: * @Entity e @Table(name = "series"): Estas são anotações que indicam que a classe Serie é um modelo para uma tabela chamada "series" no nosso banco de dados. Isso significa que podemos guardar objetos Serie diretamente no banco! * id: É um número único que identifica cada série no sistema. Pense nele como o número de registro de cada livro. * titulo, totalTemporadas, avaliacao, etc.: São os campos que guardam as informações da série. * genero: Note que o tipo de genero é Categoria, não String! Isso nos leva à próxima entidade. * episodios: Esta é uma lista que guarda todos os objetos Episodio que pertencem a esta série. Falaremos mais sobre ela em breve.

    A Entidade Categoria: Tipos Definidos

    A Categoria é um tipo especial de "entidade" chamada enum (de "enumeração"). Ela não é uma série ou um episódio, mas ajuda a manter os dados do genero de forma organizada e consistente.

    Pense nela como uma lista pré-definida de rótulos que você só pode usar. Isso evita erros de digitação e garante que todos os gêneros sejam sempre escritos da mesma forma.

    // src/main/java/br/com/alura/ScreenMatch/entities/Categoria.java
package br.com.alura.ScreenMatch.entities;

public enum Categoria {
    ROMANCE("Romance", "Romance"),
    COMEDIA("Comedy", "Comédia"),
    DRAMA("Drama", "Drama"),
    CRIME("Crime", "Crime"),
    ACAO("Action", "Ação");

    private String categoriaOmdb; // Usado para converter de um serviço externo
    private String categoriaPortugues; // O nome que usamos no aplicativo

    Categoria(String categoriaOmdb, String categoriaPortugues) {
        this.categoriaOmdb = categoriaOmdb;
        this.categoriaPortugues = categoriaPortugues;
    }

    // Método para encontrar a Categoria a partir de um texto (por exemplo, "Comedy")
    public static Categoria fromString(String text) {
        for (Categoria categoria : Categoria.values()) {
            if (categoria.categoriaOmdb.equalsIgnoreCase(text)) {
                return categoria;
            }
        }
        throw new IllegalArgumentException("Nenhuma categoria encontrada: " + text);
    }
    // ... outros métodos, como fromPortugues, omitidos para brevidade
}
    Explicação: * Cada item (como ROMANCE, COMEDIA) é uma constante. * Cada constante guarda dois nomes: um que pode vir de uma API externa (como "Comedy" do OMDB) e outro em português ("Comédia") para nosso aplicativo. * O método fromString é muito útil: se recebermos o texto "Comedy" de um site, ele automaticamente converte para o nosso tipo Categoria.COMEDIA. Isso padroniza os dados.

    A Entidade Episodio: Os Detalhes de Cada Parte

    A classe Episodio é o "cartão de identificação" para cada episódio individual de uma série.

    // src/main/java/br/com/alura/ScreenMatch/entities/Episodio.java
package br.com.alura.ScreenMatch.entities;

import jakarta.persistence.*; // Para trabalhar com banco de dados
import java.time.LocalDate;

@Entity // Indica que esta classe é uma entidade para o banco de dados
@Table(name = "episodios") // Define o nome da tabela no banco de dados
public class Episodio {
    @Id // Indica que 'id' é a chave primária
    @GeneratedValue(strategy = GenerationType.IDENTITY) // Gera o ID automaticamente
    private Long id;
    private Integer temporada;
    private String titulo;
    private Integer numeroEpisodio;
    private Double avaliacao;
    private LocalDate dataLancamento;

    @ManyToOne // Indica que muitos Episódios podem pertencer a UMA Serie
    private Serie serie; // A qual série este episódio pertence

    public Episodio(){ } // Construtor padrão

    // Métodos como getters e setters seriam definidos aqui...
    public String getTitulo() { return titulo; }
    public void setTitulo(String titulo) { this.titulo = titulo; }
    // ... e muitos outros para cada campo
}
    Explicação: * id: Identificador único do episódio. * temporada, titulo, numeroEpisodio, etc.: Informações específicas de um episódio. * @ManyToOne: Esta é a parte crucial! Ela diz que muitos Episodios (Many) podem estar associados a apenas uma Serie (One). É assim que conectamos um episódio à sua série principal. * private Serie serie;: Este campo dentro de Episodio guarda a referência para o objeto Serie ao qual ele pertence.

    Como as Entidades Trabalham Juntas

    As entidades Serie e Episodio não vivem isoladas; elas são conectadas. Uma Serie tem uma lista de Episodios, e cada Episodio "sabe" a qual Serie ele pertence.

    Veja um exemplo de como os objetos se relacionam na memória do programa:

    sequenceDiagram

    participant ObjetoSerie as Objeto Série
    participant ObjetoEpisodio1 as Objeto Episódio 1
    participant ObjetoEpisodio2 as Objeto Episódio 2

    Aplicacao->>ObjetoSerie: Criar nova Série("Stranger Things")
    Aplicacao->>ObjetoEpisodio1: Criar novo Episódio("Cap. 1")
    Aplicacao->>ObjetoEpisodio2: Criar novo Episódio("Cap. 2")

    Aplicacao->>ObjetoSerie: Adicionar Episódio 1 à lista de episódios
    ObjetoEpisodio1->>ObjetoSerie: Definir que pertence à "Stranger Things"

    Aplicacao->>ObjetoSerie: Adicionar Episódio 2 à lista de episódios
    ObjetoEpisodio2->>ObjetoSerie: Definir que pertence à "Stranger Things"

    Quando criamos uma Serie e seus Episodios, estamos preenchendo esses "cartões" e ligando-os uns aos outros. Por exemplo, quando adicionamos um episódio à lista de episodios de uma Serie, também garantimos que o campo serie dentro daquele Episodio aponte de volta para a Serie correta. Isso é feito no método setEpisodio da classe Serie:

    // Parte do arquivo src/main/java/br/com/alura/ScreenMatch/entities/Serie.java
// ...
   public void setEpisodio(List<Episodio> episodios) {
      // Para cada episódio na lista que estamos recebendo...
      episodios.forEach(e -> e.setSerie(this)); // ...dizemos a ele a qual série ele pertence (esta série!)
      this.episodios = episodios; // Finalmente, salvamos a lista de episódios
   }
// ...
    Explicação: Esta pequena linha episodios.forEach(e -> e.setSerie(this)); é muito importante. Ela garante que, quando você adiciona uma lista de episódios a uma série, cada episódio "saiba" a qual série ele está ligado. O this aqui se refere ao objeto Serie atual.

    Conclusão

    Neste capítulo, você aprendeu sobre as Entidades de Dados no projeto ScreenMatch: * A classe Serie representa uma série de TV completa, com seus detalhes e uma lista de episódios. * A classe Episodio representa um único episódio, com seus próprios detalhes e uma ligação de volta para a série à qual pertence. * O enum Categoria ajuda a padronizar os gêneros das séries, garantindo consistência.

    Essas entidades são a base do nosso aplicativo, pois elas definem a "linguagem" que usamos para falar sobre séries e episódios.
