    Chapter 3: Conversor de Dados JSON

    Bem-vindo(a) ao terceiro capítulo do nosso tutorial do ScreenMatch! Nos capítulos anteriores, montamos a base do nosso projeto. No Capítulo 1: Entidades de Dados, definimos as estruturas (Serie e Episodio) que o nosso programa usa para organizar as informações. Em seguida, no Capítulo 2: Serviço de Requisições Web, aprendemos a buscar essas informações na internet, especificamente da API do OMDb.

    No final do Capítulo 2, vimos que o Serviço de Requisições Web nos entrega os dados da série como um grande texto no formato JSON. Esse texto é perfeito para computadores trocarem informações, mas para o nosso programa Java, ele ainda é apenas uma String.

    A pergunta é: como pegamos esse monte de texto e o transformamos em objetos Java de verdade, como a nossa Serie e Episodio, que podemos facilmente manipular, exibir e salvar?

    É exatamente isso que o Conversor de Dados JSON faz!

    A Ponte entre o Texto e o Objeto: O "Tradutor" de Dados

    Imagine que você está em um país estrangeiro e alguém te entrega um documento importante escrito em um idioma que você não entende. Você precisa de um tradutor para transformar aquele texto em algo que faça sentido para você.

    No ScreenMatch, o Conversor de Dados JSON é o nosso "tradutor" especializado. Ele pega o "idioma" JSON que veio da internet e o transforma em objetos Java que o restante do aplicativo pode manipular facilmente. É como organizar os dados brutos em uma planilha limpa e fácil de usar.

    Exemplo de uso central: No capítulo anterior, recebemos algo assim: 

    {"Title":"Game of Thrones","Year":"2011–2019","totalSeasons":"8","imdbRating":"9.2","Genre":"Fantasy, Drama, Action", ...}
    Nosso objetivo é transformar isso em um objeto Java que contenha titulo (Game of Thrones), totalTemporadas (8), avaliacao (9.2), etc., de forma organizada.

    O Coração do Conversor: A Biblioteca Jackson

    Para fazer essa "tradução" do JSON para objetos Java, não vamos reinventar a roda. Usaremos uma biblioteca superpoderosa e popular chamada Jackson. Ela é especialista em lidar com JSON no Java, tornando a tarefa muito mais simples.

    "Mini-Cartões" de Dados Temporários: Os Records

    Antes de converter diretamente para as nossas classes Serie e Episodio (vistas no Capítulo 1: Entidades de Dados), temos um passo intermediário. O JSON que vem da internet pode ter muitos campos que não nos interessam, ou nomes de campos diferentes dos que usamos em nossas classes.

    Para lidar com isso de forma eficiente, criamos o que chamamos de records em Java (uma funcionalidade mais recente da linguagem). Eles são como "mini-cartões" de dados temporários, feitos sob medida para "capturar" as informações exatas que queremos do JSON, com os nomes exatos que ele nos dá.

    Vamos ver um exemplo com DadosSerie, que é o nosso record para os dados de uma série que vêm do OMDb:

    // src/main/java/br/com/alura/ScreenMatch/entities/DadosSerie.java
package br.com.alura.ScreenMatch.entities;

import com.fasterxml.jackson.annotation.JsonAlias;
import com.fasterxml.jackson.annotation.JsonIgnoreProperties;

@JsonIgnoreProperties(ignoreUnknown = true)
public record DadosSerie(@JsonAlias("Title") String titulo,
                         @JsonAlias("totalSeasons") Integer totalTemporadas,
                         @JsonAlias("imdbRating") String avaliacao) {
}
    Explicação: * record DadosSerie(...): Indica que esta é uma classe record com campos (titulo, totalTemporadas, avaliacao). Records são ideais para segurar dados de forma simples. * @JsonIgnoreProperties(ignoreUnknown = true): Esta anotação diz ao Jackson para ignorar qualquer campo no JSON que não esteja listado neste record. Se o JSON tiver "Director" ou "Awards" e não quisermos esses dados, o Jackson simplesmente os ignora sem causar erro. * @JsonAlias("Title") String titulo: Esta é a parte mais importante! O JSON da API do OMDb usa o nome "Title" para o título da série. Mas em nosso record, queremos chamá-lo de titulo. O @JsonAlias faz essa "ponte", dizendo ao Jackson: "Quando vir 'Title' no JSON, coloque o valor no campo titulo deste record". O mesmo acontece para "totalSeasons" virar totalTemporadas e "imdbRating" virar avaliacao.

    Temos records semelhantes para outros tipos de dados que vêm da API: * DadosEpisodios: Para os detalhes de cada episódio. * DadosTemporadas: Para agrupar uma lista de episódios dentro de uma temporada.

    Eles funcionam da mesma forma, usando @JsonAlias para mapear os nomes do JSON para os nomes mais convenientes em nossos records.

    Como Usar o Conversor: A Classe ConverterDados

    Agora que entendemos os records, vamos ver como usar o nosso "tradutor" principal, a classe ConverterDados. Ela possui um método mágico chamado obterDados que faz toda a transformação.

    Primeiro, temos uma interface que define o contrato do nosso conversor. Uma interface é como um "projeto" que diz o que uma classe deve ser capaz de fazer:

    // src/main/java/br/com/alura/ScreenMatch/service/IConverterDados.java
package br.com.alura.ScreenMatch.service;

public interface IConverterDados {
    <T> T obterDados(String json, Class<T> classe);
}
    Explicação: * interface IConverterDados: Define que esta é uma interface. * <T> T obterDados(String json, Class<T> classe): Este método diz que qualquer classe que implementar IConverterDados deve ter um método obterDados. * <T>: Significa que este método é "genérico", ele pode trabalhar com qualquer tipo de dado (como DadosSerie, DadosEpisodios, etc.). * json: É o texto JSON que veio da internet. * classe: É o "mini-cartão" (record ou outra classe) para o qual queremos converter o JSON (por exemplo, DadosSerie.class).

    Agora, vamos ver a implementação real do ConverterDados:

    // src/main/java/br/com/alura/ScreenMatch/service/ConverterDados.java
package br.com.alura.ScreenMatch.service;

import com.fasterxml.jackson.core.JsonProcessingException;
import com.fasterxml.jackson.databind.ObjectMapper;

public class ConverterDados implements IConverterDados {
    // Objeto principal do Jackson que faz a mágica de conversão
    private ObjectMapper mapper = new ObjectMapper();

    @Override
    public <T> T obterDados(String json, Class<T> classe) {
        try {
            // AQUI A MÁGICA ACONTECE:
            // O ObjectMapper lê o texto JSON e tenta transformá-lo em um objeto
            // do tipo de 'classe' que você especificou (ex: DadosSerie.class)
            return mapper.readValue(json, classe);
        } catch (JsonProcessingException e) {
            // Se houver um problema na conversão (JSON mal formatado, etc.)
            // lançamos uma exceção para avisar que algo deu errado.
            throw new RuntimeException("Erro ao processar JSON: " + e.getMessage(), e);
        }
    }
}
    Explicação linha a linha: * private ObjectMapper mapper = new ObjectMapper();: Aqui, criamos uma "ferramenta" do Jackson chamada ObjectMapper. É ela quem realmente sabe como ler e escrever JSON. * return mapper.readValue(json, classe);: Esta é a linha crucial! * mapper.readValue(): É o método do ObjectMapper que lê o json (o texto) e tenta transformá-lo em um objeto da classe que você passou como segundo argumento. Se você passou DadosSerie.class, ele vai tentar criar um objeto DadosSerie preenchido com os dados do JSON. * try-catch: Como a conversão de texto para objeto pode falhar (por exemplo, se o JSON estiver mal formatado ou faltarem chaves importantes), o Java exige que lidemos com a JsonProcessingException. O try-catch garante que nosso programa não trave se algo der errado, permitindo que a gente trate o problema.

    Exemplo de uso prático (como você o usaria no seu programa): Imagine que você já buscou o JSON da API do OMDb (como vimos no Capítulo 2: Serviço de Requisições Web):

    // Em alguma parte do seu código, talvez na sua classe Main
import br.com.alura.ScreenMatch.service.ScreenService;
import br.com.alura.ScreenMatch.service.ConverterDados;
import br.com.alura.ScreenMatch.entities.DadosSerie; // Nosso "mini-cartão" de dados

public class ExemploConversor {
    public static void main(String[] args) {
        ScreenService webService = new ScreenService(); // Nosso explorador
        ConverterDados conversor = new ConverterDados(); // Nosso tradutor

        // 1. Obter o JSON da internet (do Capítulo 2)
        String enderecoSerie = "https://www.omdbapi.com/?t=Game+of+Thrones&apikey=SUA_CHAVE_AQUI";
        String jsonDaSerie = webService.obterDados(enderecoSerie);
        System.out.println("JSON recebido:\n" + jsonDaSerie.substring(0, 100) + "..."); // Apenas um pedaço para não poluir

        // 2. Converter o JSON para um objeto DadosSerie
        DadosSerie dadosTemporarios = conversor.obterDados(jsonDaSerie, DadosSerie.class);

        System.out.println("\nDados convertidos para objeto Java (DadosSerie):");
        System.out.println("Título: " + dadosTemporarios.titulo());
        System.out.println("Total de Temporadas: " + dadosTemporarios.totalTemporadas());
        System.out.println("Avaliação: " + dadosTemporarios.avaliacao());
    }
}

    Por Dentro do Conversor: A "Mágica" do ObjectMapper

    Para entender o fluxo completo, visualize o seguinte:

    sequenceDiagram
    participant Aplicacao as Sua Aplicação
    participant ScreenService as Serviço Web
    participant OMDbAPI as OMDb API
    participant ConverterDados as Conversor JSON
    participant ObjectMapper as Motor Jackson

    Aplicacao->>ScreenService: "Busque dados da série X"
    ScreenService->>OMDbAPI: Requisição HTTP
    OMDbAPI-->>ScreenService: Resposta JSON (Texto)
    ScreenService-->>Aplicacao: Texto JSON da série

    Aplicacao->>ConverterDados: "Converte este JSON para DadosSerie.class"
    ConverterDados->>ObjectMapper: "Por favor, leia este JSON (texto) e crie um objeto DadosSerie"
    ObjectMapper->>ObjectMapper: Analisa o texto JSON + Mapeia para campos do DadosSerie (via @JsonAlias)
    ObjectMapper-->>ConverterDados: Objeto DadosSerie preenchido
    ConverterDados-->>Aplicacao: Objeto DadosSerie (limpo e pronto para uso!)
    1. A Sua Aplicação (você, em seu código Main) pede ao ScreenService para obter os dados de uma série da internet.
    2. O ScreenService faz a "viagem" (requisição HTTP) até a OMDbAPI e recebe um texto JSON como resposta.
    3. O ScreenService entrega esse texto JSON de volta para a Sua Aplicação.
    4. Agora, a Sua Aplicação passa esse texto JSON para o ConverterDados, junto com o tipo de "mini-cartão" (DadosSerie.class) que queremos que ele crie.
    5. O ConverterDados internamente usa o ObjectMapper (o "motor" do Jackson).
    6. O ObjectMapper pega o texto JSON, lê cada pedacinho, e graças às anotações @JsonAlias nos nossos records (DadosSerie), ele sabe exatamente qual informação do JSON vai em qual campo do nosso objeto Java.
    7. Finalmente, o ObjectMapper constrói o objeto DadosSerie (ou DadosEpisodios, etc.) e o devolve ao ConverterDados, que o entrega de volta para a Sua Aplicação.

    Com esse objeto DadosSerie em mãos, podemos então usá-lo para criar uma instância da nossa entidade Serie (do Capítulo 1: Entidades de Dados), preenchendo todos os campos bonitinhos. É assim que os dados brutos da internet se transformam em informações estruturadas dentro do nosso programa!
