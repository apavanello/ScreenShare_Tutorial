    Chapter 4: Repositório de Séries

    Bem-vindo(a) ao quarto capítulo do nosso tutorial do ScreenMatch! Nos capítulos anteriores, montamos a base para que nosso aplicativo pudesse entender e obter informações sobre séries. No Capítulo 1: Entidades de Dados, definimos como as informações de Serie e Episodio seriam organizadas. No Capítulo 2: Serviço de Requisições Web, aprendemos a buscar esses dados brutos na internet. E no Capítulo 3: Conversor de Dados JSON, vimos como transformar esses dados brutos em objetos Java úteis.

    Agora que temos nossos objetos Serie e Episodio bonitinhos e preenchidos, o que fazemos com eles? Se desligarmos o programa, todas essas informações se perdem! Precisamos de uma forma de guardar esses dados permanentemente, encontrá-los facilmente mais tarde, atualizá-los ou até mesmo deletá-los.

    É exatamente para isso que serve o Repositório de Séries!

    O "Arquivista" do Nosso Banco de Dados

    Imagine o Repositório de Séries como o "arquivista" ou "bibliotecário" do seu banco de dados. Ele é o responsável exclusivo por todas as tarefas relacionadas a guardar, buscar, atualizar e deletar informações sobre as séries e seus episódios.

    Qual problema ele resolve? Sem o repositório, toda vez que quiséssemos salvar uma série, teríamos que escrever um código complexo para interagir diretamente com o banco de dados (por exemplo, usando comandos SQL). Isso seria trabalhoso e propenso a erros.

    O repositório simplifica tudo! Em vez de o seu programa precisar saber os detalhes de como "conversar" com o banco de dados, ele apenas pede ao Repositório para, por exemplo, "salvar esta nova série" ou "encontrar todas as séries de um ator". O Repositório cuida de toda a complexidade por trás dos panos.

    Nosso principal caso de uso aqui: Vamos focar em como o Repositório nos permite salvar uma nova série no banco de dados e buscá-la posteriormente.

    Conceito Chave: JpaRepository - A Mágica do Spring Data JPA

    No ScreenMatch, usamos uma ferramenta poderosa do ecossistema Spring chamada Spring Data JPA. Ela nos ajuda a interagir com o banco de dados de uma maneira muito elegante e com pouquíssimo código.

    O coração dessa interação é a interface JpaRepository.

    Por que uma interface e não uma classe? Uma interface é como um "contrato" ou um "plano" que define o que uma classe deve ser capaz de fazer. A mágica é que o Spring Data JPA é tão inteligente que ele automaticamente cria uma classe que implementa essa interface para você, no momento em que seu programa inicia. Essa classe gerada sabe como conversar com o banco de dados!

    Veja a nossa interface SerieRepository:

    // src/main/java/br/com/alura/ScreenMatch/repository/SerieRepository.java
package br.com.alura.ScreenMatch.repository;

import br.com.alura.ScreenMatch.entities.Serie; // Importa nossa entidade Serie
import org.springframework.data.jpa.repository.JpaRepository; // A interface mágica!
import org.springframework.data.jpa.repository.Query; // Para consultas mais complexas

import java.util.List;
import java.util.Optional;

// A interface do nosso repositório para a entidade Serie
// <Serie, Long> indica que ele gerencia a entidade Serie e o ID dela é do tipo Long
public interface SerieRepository extends JpaRepository<Serie, Long> {

    // Método que o Spring Data JPA entende automaticamente!
    Optional<Serie> findByTituloContainingIgnoreCase(String nomeSerie);

    // Exemplo de outro método que o Spring Data JPA entende pelo nome
    List<Serie> findTop5ByOrderByAvaliacaoDesc();

    // Exemplo de uma consulta mais complexa, escrita em JPQL (parecido com SQL)
    @Query("select s from Serie s WHERE s.totalTemporadas <= :totalTemporadas AND s.avaliacao >= :avaliacao ")
    List<Serie> seriePorTemporadaEAvaliacao(int totalTemporadas, double avaliacao);

    // ... outros métodos seriam definidos aqui ...
}
    Explicação: * public interface SerieRepository extends JpaRepository<Serie, Long>: É aqui que a mágica começa! * SerieRepository: É o nome da nossa interface, nosso "arquivista" para séries. * extends JpaRepository: Diz ao Spring que esta interface vai herdar todos os métodos básicos de um repositório (como save para salvar, findById para buscar por ID, findAll para buscar todos, etc.) sem que a gente precise escrevê-los. * <Serie, Long>: Os dois tipos dentro do < > são importantes: * Serie: É a Entidade de Dados (do Capítulo 1: Entidades de Dados) que este repositório vai gerenciar. * Long: É o tipo de dado da chave primária (ID) da sua entidade Serie. (Lembre-se que em Serie.java definimos private Long id;). * Optional<Serie> findByTituloContainingIgnoreCase(String nomeSerie): Este é um exemplo de um método que o Spring Data JPA consegue implementar apenas pelo nome! * findBy: Indica que estamos buscando (find) algo. * Titulo: Indica que a busca será pelo campo titulo da nossa entidade Serie. * ContainingIgnoreCase: Diz para buscar títulos que "contenham" (Containing) a nomeSerie que passarmos, ignorando se é maiúscula ou minúscula (IgnoreCase). * Optional<Serie>: O retorno é um Optional porque a série pode ou não ser encontrada. * @Query(...): Para buscas mais complexas ou que não seguem o padrão de nomes do Spring Data JPA, podemos escrever nossas próprias "consultas" usando a anotação @Query. A linguagem dentro do @Query é chamada JPQL, que é muito parecida com SQL, mas trabalha com os nomes das suas classes e campos Java (Serie s em vez de series).

    Como Usar o Repositório: Salvando e Buscando Séries

    Agora que temos nossa interface SerieRepository, vamos ver como usá-la para salvar e buscar séries.

    Imagine que você já tem um objeto Serie pronto para ser salvo (talvez você o tenha criado a partir dos dados obtidos da internet e convertidos nos capítulos anteriores).

    // Em alguma parte da sua aplicação, geralmente na classe principal (Main)
// ou em um serviço que gerencia a lógica de negócio.
import br.com.alura.ScreenMatch.entities.Serie;
import br.com.alura.ScreenMatch.repository.SerieRepository; // Nosso repositório
import java.util.Optional;

public class ExemploUsoRepositorio {

    private SerieRepository repositorio; // O Spring "injeta" este objeto para nós

    // Construtor ou método para configurar o repositório
    public ExemploUsoRepositorio(SerieRepository repositorio) {
        this.repositorio = repositorio;
    }

    public void demonstrarUso() {
        // --- CENÁRIO 1: Salvando uma nova série ---
        Serie novaSerie = new Serie();
        novaSerie.setTitulo("The Witcher");
        novaSerie.setTotalTemporadas(3);
        novaSerie.setAvaliacao(8.2);
        // ... definir outros campos como genero, sinopse, etc. ...

        System.out.println("Tentando salvar a série: " + novaSerie.getTitulo());
        repositorio.save(novaSerie); // A LINHA MÁGICA: SALVA NO BANCO!
        System.out.println("Série salva com sucesso! ID gerado: " + novaSerie.getId());

        // --- CENÁRIO 2: Buscando uma série pelo título ---
        String tituloParaBuscar = "witcher";
        System.out.println("\nBuscando série com título contendo: '" + tituloParaBuscar + "'");
        Optional<Serie> serieEncontrada = repositorio.findByTituloContainingIgnoreCase(tituloParaBuscar);

        if (serieEncontrada.isPresent()) {
            System.out.println("Série encontrada: " + serieEncontrada.get().getTitulo());
            System.out.println("Avaliação: " + serieEncontrada.get().getAvaliacao());
        } else {
            System.out.println("Nenhuma série encontrada com o título: " + tituloParaBuscar);
        }
    }
}
    Explicação: 1. private SerieRepository repositorio;: Declaramos uma variável do tipo da nossa interface SerieRepository. O Spring cuida de criar e fornecer uma instância real dessa interface para nós, com todas as funcionalidades. 2. repositorio.save(novaSerie);: É assim que você salva uma série! Você passa o objeto Serie para o método save, e o Spring Data JPA faz todo o trabalho de gerar o comando SQL INSERT e executá-lo no banco de dados. Se a série já existe e tem um ID, ele fará um UPDATE. 3. Optional<Serie> serieEncontrada = repositorio.findByTituloContainingIgnoreCase(tituloParaBuscar);: Para buscar, chamamos o método que definimos na interface. Ele retorna um Optional<Serie>, que é uma forma segura de lidar com resultados que podem não existir (evita erros se a série não for encontrada). 4. if (serieEncontrada.isPresent()) { ... }: Verificamos se a série foi realmente encontrada antes de tentar acessar seus dados com serieEncontrada.get().

Avaliação: 8.2

    Por Dentro do Repositório: A Mágica por Trás da Cena

    Você notou que nunca escrevemos uma linha de SQL (INSERT, SELECT, UPDATE)? Essa é a grande vantagem do Spring Data JPA e do JpaRepository.

    O que acontece quando você chama repositorio.save(novaSerie) ou repositorio.findByTitulo(...)?

    1. Sua Aplicação (o código que você escreveu) chama um método na interface SerieRepository (por exemplo, save ou findByTitulo).
    2. Como SerieRepository é uma interface, ela não tem implementação própria. Mas o Spring Data JPA é configurado para "escutar" essas chamadas.
    3. No momento em que seu aplicativo é iniciado, o Spring Data JPA automaticamente cria uma classe invisível que implementa a interface SerieRepository. Essa classe gerada sabe como traduzir as chamadas dos seus métodos (como save ou findByTituloContainingIgnoreCase) para comandos SQL reais.
    4. Essa classe gerada se conecta ao Banco de Dados (que pode ser um PostgreSQL, MySQL, H2, etc.).
    5. Ela então envia o comando SQL apropriado para o banco.
    6. O Banco de Dados executa o comando e retorna o resultado (por exemplo, "salvo com sucesso" ou os dados da série encontrada).
    7. A classe gerada pelo Spring Data JPA pega o resultado do banco, o transforma de volta em objetos Java (Serie ou List<Serie>) e o entrega de volta para a sua SerieRepository (a "interface" que você chamou).
    8. Finalmente, o resultado (o objeto Serie salvo, ou a Optional<Serie> encontrada) é retornado para a Sua Aplicação.

    Visualize o fluxo:

    sequenceDiagram
    participant Aplicacao as Sua Aplicação
    participant SerieRepositoryInterface as SerieRepository (Interface)
    participant SpringDataJPA as Spring Data JPA (A Mágica)
    participant BancoDeDados as Banco de Dados

    Aplicacao->>SerieRepositoryInterface: repositorio.save(novaSerie)
    SerieRepositoryInterface->>SpringDataJPA: Chamar método 'save'
    SpringDataJPA->>SpringDataJPA: Converte 'save' em SQL (INSERT INTO ...)
    SpringDataJPA->>BancoDeDados: Executa SQL (INSERT)
    BancoDeDados-->>SpringDataJPA: Confirmação / ID gerado
    SpringDataJPA-->>SerieRepositoryInterface: Retorna Serie atualizada
    SerieRepositoryInterface-->>Aplicacao: Serie salva (com ID)

    Aplicacao->>SerieRepositoryInterface: repositorio.findByTituloContainingIgnoreCase("titulo")
    SerieRepositoryInterface->>SpringDataJPA: Chamar método 'findByTituloContainingIgnoreCase'
    SpringDataJPA->>SpringDataJPA: Converte nome em SQL (SELECT * FROM ... WHERE titulo ILIKE '%titulo%')
    SpringDataJPA->>BancoDeDados: Executa SQL (SELECT)
    BancoDeDados-->>SpringDataJPA: Retorna dados da série (se houver)
    SpringDataJPA->>SpringDataJPA: Converte dados para objeto Serie
    SpringDataJPA-->>SerieRepositoryInterface: Retorna Optional<Serie>
    SerieRepositoryInterface-->>Aplicacao: Optional<Serie>

    É importante notar que o Spring Data JPA cuida de toda a "burocracia" de conectar, enviar SQL e converter resultados, permitindo que você se concentre na lógica de negócio do seu aplicativo.
