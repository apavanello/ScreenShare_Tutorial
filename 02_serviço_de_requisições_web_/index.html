    Chapter 2: Serviço de Requisições Web

    Bem-vindo(a) ao segundo capítulo do nosso tutorial do ScreenMatch! No Capítulo 1: Entidades de Dados, aprendemos como organizar as informações sobre séries e episódios dentro do nosso programa. Vimos que temos "cartões" (nossas entidades Serie e Episodio) prontos para guardar todos os detalhes.

    Mas de onde vêm esses detalhes? Nosso aplicativo não nasce sabendo tudo sobre "Stranger Things" ou "The Crown". Ele precisa buscar essas informações em algum lugar. E é exatamente aí que entra o Serviço de Requisições Web!

    A Necessidade de "Explorar" a Internet

    Imagine que você está organizando sua coleção de DVDs e quer adicionar um filme novo que acabou de ver. Você não sabe todos os detalhes de cabeça (diretor, elenco completo, sinopse). O que você faz? Provavelmente, pega seu celular e pesquisa no Google ou em um site especializado como o IMDb.

    No mundo da programação, nosso aplicativo faz algo parecido. Para obter dados sobre uma série que ainda não temos, ele precisa "perguntar" a um serviço na internet.

    Nosso Serviço de Requisições Web funciona como um "explorador" digital. Você diz a ele o que procurar (o título da série, por exemplo), e ele faz a "viagem" pela internet, busca a "resposta" (os dados da série em formato de texto especial chamado JSON) e a entrega de volta ao programa. Ele é essencial para trazer para dentro do nosso aplicativo dados de séries que ainda não estão salvas localmente.

    Como Funciona a "Viagem" Digital?

    Vamos detalhar o processo de como o nosso "explorador" consegue os dados:

    1. O Destino (URI): Primeiro, o explorador precisa saber para onde ir. Na internet, isso é um endereço, como um "CEP" digital, chamado URI (Uniform Resource Identifier). No nosso caso, o destino será a API (Application Programming Interface) do OMDb (Open Movie Database), que é um banco de dados de filmes e séries.

    2. A Pergunta (Requisição HTTP): Uma vez no destino, o explorador precisa "fazer a pergunta" de uma forma que o site entenda. Isso é chamado de Requisição HTTP. É como uma mensagem que diz: "Olá, OMDb! Poderia me dar os dados da série 'Game of Thrones'?".

    3. O Mensageiro (HTTP Client): Para enviar essa pergunta, precisamos de um "mensageiro" especializado. No Java, usamos o HttpClient, que é como um carteiro super eficiente que sabe enviar e receber mensagens pela internet.

    4. A Resposta (Resposta HTTP e JSON): O OMDb, ao receber a pergunta, processa-a e envia de volta uma Resposta HTTP. Dentro dessa resposta, vem o "pacote de dados", que geralmente está no formato JSON (JavaScript Object Notation). JSON é um jeito padronizado de organizar informações em texto, como uma lista bem estruturada de características e seus valores (ex: "título": "Stranger Things", "avaliação": "8.7").

    Nosso "Explorador" em Ação: A Classe ScreenService

    No ScreenMatch, o papel de "explorador" é desempenhado pela classe ScreenService. Ela tem um método principal chamado obterDados que faz toda essa "viagem" por você.

    Vamos ver como usamos ele:

    // No seu código principal (ex: na classe Main)
import br.com.alura.ScreenMatch.service.ScreenService; // Importamos nosso explorador

public class ExemploUso {
    public static void main(String[] args) {
        ScreenService service = new ScreenService(); // Criamos um novo explorador

        String enderecoApi = "https://www.omdbapi.com/?t=Game+of+Thrones&apikey=SUA_CHAVE_AQUI";

        // Pedimos para o explorador obter os dados
        String dadosJson = service.obterDados(enderecoApi);

        System.out.println("Dados obtidos da internet (formato JSON):");
        System.out.println(dadosJson);
    }
}
    Explicação: * ScreenService service = new ScreenService();: Aqui, criamos uma "instância" do nosso explorador. É como tirar o explorador da caixa e prepará-lo para a viagem. * String enderecoApi = "...";: Este é o "endereço" completo para onde o explorador deve ir. Ele inclui o título da série (t=Game+of+Thrones) e, muito importante, a sua chave de API (apikey=SUA_CHAVE_AQUI). Essa chave é como uma permissão para usar o serviço do OMDb, e você precisa obter a sua no site deles. * String dadosJson = service.obterDados(enderecoApi);: Essa é a chamada ao nosso explorador! Pedimos a ele para ir até o enderecoApi e trazer os dados. Ele retorna uma String (um texto) que é o JSON com as informações da série.

    Por Dentro do ScreenService: Como Ele Constrói a Requisição

    Agora, vamos abrir a caixa preta e ver como a classe ScreenService faz a mágica acontecer. Ela está no arquivo src/main/java/br/com/alura/ScreenMatch/service/ScreenService.java:

    // src/main/java/br/com/alura/ScreenMatch/service/ScreenService.java
package br.com.alura.ScreenMatch.service;

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

public class ScreenService {

    public String obterDados(String dados) {
        // 1. Criar o mensageiro HTTP
        HttpClient client = HttpClient.newHttpClient();

        // 2. Montar a "pergunta" (requisição) com o endereço
        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create(dados)) // O "dados" que recebemos é o endereço
                .build();

        // 3. Enviar a pergunta e esperar pela resposta
        HttpResponse<String> response = null;
        try {
            response = client.send(request, HttpResponse.BodyHandlers.ofString());
        } catch (IOException e) {
            // Em caso de erro de conexão (ex: internet caiu)
            throw new RuntimeException("Erro de IO ao obter dados: " + e.getMessage());
        } catch (InterruptedException e) {
            // Em caso de interrupção (ex: programa foi parado enquanto esperava)
            throw new RuntimeException("Requisição interrompida: " + e.getMessage());
        }

        // 4. Extrair o corpo da resposta (o JSON)
        String json = response.body();
        return json; // Devolve o texto JSON
    }
}
    Análise linha a linha:

    1. HttpClient client = HttpClient.newHttpClient();

      • Aqui, criamos nosso "mensageiro" HTTP. Ele será o responsável por enviar a requisição e receber a resposta.

    2. HttpRequest request = HttpRequest.newBuilder().uri(URI.create(dados)).build();

      • Esta linha constrói a "pergunta" (a requisição).
      • HttpRequest.newBuilder(): Inicia o processo de construção de uma requisição.
      • .uri(URI.create(dados)): Define o endereço (URI) para onde a requisição será enviada. O dados que passamos para o método obterDados é justamente esse endereço completo.
      • .build(): Finaliza a construção da requisição.

    3. response = client.send(request, HttpResponse.BodyHandlers.ofString());

      • Esta é a linha mais importante! O "mensageiro" (client) realmente send (envia) a request (pergunta) para a internet.
      • HttpResponse.BodyHandlers.ofString(): Diz ao mensageiro para esperar a resposta como um texto (String).
      • O resultado dessa operação é um HttpResponse<String>, que contém a resposta completa do servidor (incluindo o JSON).

    4. String json = response.body();

      • Finalmente, pegamos o "corpo" da resposta (response.body()), que é onde o texto JSON está.

    5. return json;

      • Devolvemos esse texto JSON para quem chamou o método obterDados.

    Tratamento de Erros (try-catch): As seções try { ... } catch (IOException e) { ... } catch (InterruptedException e) { ... } são essenciais para lidar com problemas. Imagine que o mensageiro tente entregar a carta, mas a internet caiu (IOException), ou o programa é desligado no meio da espera (InterruptedException). O try-catch evita que nosso programa trave, permitindo que ele "capture" e trate esses erros de forma elegante.
